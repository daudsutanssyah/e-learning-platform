### **1. Tujuan Assessment**

Assessment ini bertujuan menilai kemampuan kandidat memahami kebutuhan sederhana, merancang solusi, menulis kode yang terstruktur, dan menyelesaikan fitur utama yang dapat didemonstrasikan. Fokus penilaian adalah kualitas implementasi dan pemahaman teknis, bukan jumlah fitur atau kelengkapan fitur.

### **2. Deskripsi Produk**

Pembuatan aplikasi E-Learning sederhana. Student dapat melihat course, membuka detail course, memilih lesson, dan melihat lesson berupa video.

### **3. Aturan Umum**

-

- - Kandidat Flutter Developer mengerjakan Track B.

  - Kandidat bebas menentukan struktur proyek, database, serta pendekatan UI/UX selama sesuai kebutuhan track. Dengan ketentuan kandidat Mobile Developer menggunakan Flutter.

- System design, ERD/database design, API design (jika relevan), flowchart sederhana, dan UI/UX boleh dirancang sendiri oleh kandidat.

- AI coding assistant dan library pihak ketiga boleh digunakan. Dengan catatan kandidat harus memahami dan mampu menjelaskan kode yang dikumpulkan.

- Gunakan data dummy yang relevan dan video contoh yang aman, jangan menggunakan data dengan karakter aneh tanpa arti.

-

-

- Fitur tambahan bersifat opsional. Selesaikan fitur wajib terlebih dahulu.

- Jika ada asumsi atau batasan teknis, tuliskan secara singkat pada dokumentasi.

### **FLUTTER DEVELOPER – TRACK B**

Bangun aplikasi Flutter untuk Student. Tidak perlu membuat aplikasi Admin. Data course dan lesson dapat diperoleh dari API sederhana atau mock API dengan data yang relevan.

#### **B2. Batasan dan Catatan Teknis**

- Gunakan Flutter dan Dart. State management yang baik (Riverpod diutamakan), routing, networking, serta package video player yang sesuai. Jelaskan juga alasan pemilihannya.

- API boleh dibuat sendiri atau digantikan mock API/static JSON yang terstruktur. Jika menggunakan mock, dokumentasikan bentuk respons dan cara menggantinya dengan API sebenarnya. Dan jangan gunakan data dummy yang tidak memiliki arti.

- Pemisahan UI, pengelolaan state, bebas dilakukan. Penggunaan arsitektur yang baik akan mendapat nilai lebih. Arsitektur yang baik bukan berarti kompleks.

- Tangani loading, empty, error, dan koneksi yang gagal.

- Pastikan controller/player dikelola dengan benar: pause/dispose saat halaman ditutup atau lesson diganti.

### **4. Desain System dan UI/UX**

Kandidat harus menentukan sendiri rancangan sistem dan tampilan aplikasi. Tidak ada template desain yang harus diikuti.

- System design sederhana: gambarkan komponen utama dan alur data aplikasi sesuai track.

- Untuk Track Flutter, sertakan rancangan model data dan kontrak API/mock data.

- Flowchart atau sequence diagram singkat untuk alur pengelolaan course/lesson dan pemutaran video.

- UI/UX untuk halaman yang benar-benar diimplementasikan. Kandidat bebas membuat wireframe atau prototype dengan tool pilihannya.

- Tentukan sendiri warna, typography, spacing, komponen, dan responsive behavior. Konsistensi dan kemudahan penggunaan akan dinilai.

Dokumentasi desain tidak perlu panjang. Diagram sederhana yang menjelaskan keputusan kandidat sudah cukup.

### **5. Deliverables**

- Source code dalam repository Git atau arsip proyek yang dapat diperiksa. Demo aplikasi tetap harus disiapkan.

- README singkat: requirement, instalasi, konfigurasi, cara menjalankan, dan akun demo jika ada.

- Dokumen/diagram system design, ERD atau model data, flowchart, serta catatan asumsi.

- Daftar keterbatasan atau bagian yang belum selesai.

### **6. Timeline dan Pengerjaan**

Pengumpulan hasil tes paling lambat 3 hari setelah File Technical Assessment diberikan kepada kandidat.

### **7. Catatan untuk Kandidat**

Kami lebih mengutamakan implementasi fitur inti yang berjalan baik, struktur kode yang mudah dipahami, dan keputusan teknis yang dapat dijelaskan daripada banyaknya fitur tambahan. Buat solusi sesederhana mungkin, tetapi tetap rapi dan dapat dikembangkan.
